# 简历项目描述 — DeepPrep 智能备考平台

## 一句话概括

AI 驱动的全学段智能备考平台，支持拍照搜题、AI 解题、间隔复习、知识图谱，已部署上线。

## 简历项目描述（适合写在简历上）

> **DeepPrep 智能备考平台** | 独立开发 | 2025.12 - 至今
>
> - 基于 Streamlit + SQLite 的全栈 Web 应用，支持多用户注册登录、6 大功能模块
> - 接入 SiliconFlow AI API（Qwen-VL + Qwen-32B），实现拍照 OCR → AI 解题 → 流式判卷 → AI 答疑 → 同类题生成的完整智能链路
> - 实现 SM-2 间隔重复算法，根据答题正确率自动调整复习间隔（10 分钟 → 1 天 → 7 天 → 15 天）
> - 基于 Plotly 实现交互式知识图谱，按学科展示知识点掌握度
> - 已部署至 Streamlit Cloud，可在线体验

## 面试可能被问到的问题 & 回答要点

### Q1: 为什么选 Streamlit 而不是 React + Flask？
**A:** 目标是快速上线验证产品想法。Streamlit 能让我一个人用 Python 完成前后端，把精力集中在 AI 功能和产品逻辑上。对秋招作品集来说，功能完整度比技术栈高级更重要。

### Q2: SM-2 算法怎么实现的？
**A:** 这是 Anki 等闪卡软件常用的记忆算法。核心是：答对 → 记忆强度 +1 → 间隔翻倍；答错 → 记忆强度 -2 → 重置为 10 分钟。用户在复习时提交答案 → AI 判卷 → 根据结果更新下次复习时间。代码在 db_manager.py 的 update_question_mastery 函数中。

### Q3: AI 调用怎么处理失败和超时？
**A:** 封装了 friendly_error() 统一异常映射（超时、限流、鉴权失败等 → 中文提示）。OCR 有重试机制。流式输出让用户不用干等。判卷有保守策略 —— JSON 解析失败默认判错。

### Q4: 多用户数据怎么隔离的？
**A:** 所有数据库查询都带 user_id 过滤。密码用 SHA-256 + 随机盐哈希。复习中的临时状态用 {user_id}_{question_id} 组合键存储，防止多用户数据混淆。

### Q5: 遇到的最大挑战是什么？
**A:** LaTeX 公式渲染。OCR 返回的公式可能包含 `\[...\]`、中文标点、转义错误等。我写了一个 clean_latex() 正则清洗管道：先保护 `$$...$$` → 处理 `$...$` → 转换 `\[...\]` → 修复中文标点 → 恢复保护块。还有一个坑是 Streamlit 的 `st.button` 在嵌套 columns 中点击可能静默失败，通过 on_click 回调 + pending navigation 机制解决了。

### Q6: 这个项目有用户使用吗？
**A:** 目前是作品集性质。预置了真实的 20 道大学数学/专业课题目。线上地址可访问，面试官可以直接体验完整流程。
